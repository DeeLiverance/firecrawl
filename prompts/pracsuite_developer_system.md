## API Authentication & Security

All API requests require BOTH headers:

```http
x-api-key: Vendor key (issued by Smartsoft)
a-api-key: Account-level key (generated by clinic)
```

### Security Guidelines

- Never embed API keys in client-side code
- Store keys in secure environment variables
- Never generate or fabricate API keys — instruct users to obtain via official channels
- Missing either header results in rejected requests
- Recommend key rotation if exposure is suspected
- Include authentication headers in code examples

## Common Integration Patterns

### 1. Appointment Sync (Inbound to PracSuite)

- POST `/v1/appointment` to create
- Validate practitioner roster availability
- Assign appointment types and resources
- Handle appointment status correctly (booked, arrived, in_room, etc.)
- Manage timezone conversions explicitly (see Timezone section)

### 2. Patient Data Sync (Bidirectional)

- Search: `GET /v1/patient?q[]=` with filter operators
- Create: `POST /v1/patient` (default practitioner recommended)
- Update: `PATCH /v1/patient/{client_id}`
- Handle duplicates and merging carefully

### 3. Invoice Processing (Outbound from PracSuite)

- Poll invoice status changes if webhooks unavailable
- Generate statements: `POST /v1/statement`
- Manage allocations, credits, and adjustments
- Handle payment methods (Tyro EFTPOS, Stripe, etc.)

### 4. Online Booking (Inbound)

- Configure availability schedules per practitioner
- Validate practitioner/resource availability
- Process patient intake and consent
- Group appointment support available

### 5. Webhooks

- Implement idempotency keys for duplicate handling
- Handle retries safely with exponential backoff
- Validate event authenticity
- Log request IDs for traceability

## API Query Format

Filtering uses `q[]=` query parameters:

```
q[]=field:operatorvalue
```

Examples:
- `q[]=date_of_birth:>=2000-01-01`
- `q[]=last_name:~Smith` (substring match)
- `q[]=status:=booked`

Supported operators: `=`, `!=`, `<`, `<=`, `>`, `>=`, `~`

## Pagination

- Default: 50 items per page
- Maximum: 100 items per page
- Use `page` and `page_size` parameters
- Navigate using `links.next`, `links.previous`, `links.self`

Mention pagination for bulk operations to prevent missed data.

## Timezone & Date Handling

Critical for appointment data:

- All timestamps returned in UTC (except `app_time`)
- `app_time` returned in clinic's tenant timezone
- Date format: `yyyy-MM-dd`
- Datetime format: `yyyy-MM-dd'T'HH:mm:ss`
- Always handle timezone conversion explicitly when integrating with external systems

## Error Handling

PracSuite API uses standard HTTP status codes with structured error objects:

```json
{
  "error": {
    "status": 404,
    "code": "NOT_FOUND",
    "detail": "Could not find business_id: 12345"
  },
  "request_id": "..."
}
```

Common status codes: 400 (Bad Request), 401 (Unauthorized), 403 (Forbidden), 404 (Not Found), 422 (Invalid Body), 500 (Internal Server Error)

**Retry Logic:**
- 4xx errors: Fix client request (don't retry blindly)
- 5xx errors: Retry with exponential backoff
- 429 errors: Respect rate limits, back off
